# حزمة تكيّة — MariaDB 10.11 وتخزين Hostinger المحلي

## محتويات الحزمة والخصوصية
- `app`: تطبيق Node.js المبني والواجهة. لا يحتوي كلمات مرور أو مفاتيح بيئة.
- `database`: هيكل القاعدة وتهيئة الإعدادات وحساب المدير الحالي فقط. **ملف seed.sql يحتوي تجزئة كلمة مرور المدير وبيانات تواصل الإعدادات؛ لا تنشره ولا تضعه داخل public_html.**
- `private-storage`: نسخ الملفات المشار إليها في إعدادات الموقع فقط، مع بيانات صلاحياتها. لا توجد ملفات حجوزات أو ملاك أو معاملات مالية.
- `manifest.json`: أحجام وبصمات الملفات للتحقق من النقل.

## المتطلبات
تطبيق Node.js بإصدار 22.9 أو أحدث ضمن 22/24، وقاعدة MariaDB 10.11 بصلاحيات إنشاء الجداول والفهارس والقيود عند الاستيراد. هذه ليست حزمة PHP أو موقعاً ثابتاً فقط. تأكد أن خدمة الاستضافة تتيح تشغيل Node.js ومجلداً دائماً خاصاً خارج جذر الويب.

## ١. تجهيز قاعدة البيانات
أنشئ قاعدة MariaDB فارغة من لوحة الاستضافة وخذ نسخة احتياطية مستقلة قبل تحديث أي قاعدة مستخدمة. اضبط `MARIADB_DATABASE_URL` ثم شغّل `npm run setup-db` داخل `app`؛ ينشئ `setup-db.js` جميع الجداول والقيود الناقصة باستخدام ملفات الهيكل الموجودة في `app/database`.

يعمل السكريبت تلقائياً أيضاً مع `npm run build` و`npm start`. أمر البناء للحزمة الجاهزة يتحقق من ملف البدء بعد تجهيز القاعدة؛ الواجهة والخادم مبنيان مسبقاً. يجب توفير الاتصال بالقاعدة وصلاحيات إنشاء الجداول والقيود أثناء البناء والتشغيل؛ الفشل يمنع بدء الخادم.

يمكن إعادة تنفيذ السكريبت دون حذف البيانات، ولا يستورد الإعدادات أو المدير ولا يعيد كتابة السجلات القديمة. يضمن وجود صفوف أقفال المعاملات من 0 إلى 10، ويحافظ على كامل المجال 0 إلى 4095 الذي يعتمد عليه التطبيق. يستخدم قفلاً مستقلاً لتسلسل عمليات التجهيز المتزامنة؛ لا يمس أقفال المعاملات النشطة.

للتثبيت الأول فقط، وبعد نجاح التجهيز، استورد `database/seed.sql` الخارجي مرة واحدة لإضافة الإعدادات وحساب المدير. لا تُعد استيراده عند التحديث. ملفات SQL الخارجية متاحة للاستيراد اليدوي عند الحاجة وليست مطلوبة مع التجهيز الآلي. السكريبت لا يهاجر تغييرات أنواع الأعمدة الموجودة تلقائياً؛ أي تغيير مستقبلي للهيكل يحتاج ترحيلاً مراجعاً.

استخدم ترميز utf8mb4 واتصالاً بتوقيت UTC. أوقف كل كتّاب النظام القديم قبل التحويل حتى لا تختلط بروتوكولات الأقفال.

## ٢. الملفات الدائمة
أنشئ مجلداً خاصاً خارج public_html وخارج مجلد إصدار التطبيق، ثم انسخ **محتويات** `private-storage` إليه، بما فيها الملفات المخفية. اجعل المجلدات بصلاحية 700 والملفات 600، وقابلة للقراءة والكتابة لحساب تشغيل Node.js فقط.

لا تقدم هذا المجلد عبر Apache أو رابط static. التطبيق يقدم الصور المسموحة من خلال API ويمنع الوصول المباشر إلى بيانات الصلاحيات والإيصالات الخاصة. لا تستبدل هذا المجلد عند تحديث التطبيق.

## ٣. إعداد التطبيق
ارفع محتويات `app` كتطبيق Node.js فقط، بما فيها `setup-db.js` ومجلد `app/database` الخاص بالهيكل؛ لا ترفع `database` الخارجي الذي يحتوي seed.sql أو تقارير الاختبار إلى جذر ويب عام. لا تقدم ملفات الهيكل كملفات static؛ الواجهة العامة فقط داخل `public`. ثبت الاعتمادات من package.json باستخدام مدير الحزم المتاح في الاستضافة، ثم شغّل `npm run build` و`npm start`.

يوجد ملف `pnpm-lock.yaml` لتثبيت الإصدارات التي اختُبرت: عند توفر pnpm استخدم `pnpm install --prod --frozen-lockfile` ثم `pnpm start`. إذا كانت لوحة الاستضافة تعتمد npm فقط، ثبت الاعتمادات بالإصدارات المباشرة المثبتة في package.json وافحص التشغيل بعد التثبيت. لا تحتوي الحزمة node_modules؛ يجب تثبيتها على الاستضافة.

في لوحة Hostinger اختر **ملف البدء `server.js`** وأمر التشغيل **`npm start`**؛ كلاهما يشغل التطبيق نفسه مرة واحدة. يحمل ملف البدء `.env` من مجلد التطبيق قبل الاتصال بالقاعدة، مع أولوية القيم التي توفرها الاستضافة، ويثبت المسارات نسبةً إلى مكان ملفه حتى عند تشغيله من دليل مختلف.

تقدم خدمة Express واحدة الواجهة من `public` وAPI من `/api`، وتستمع على `0.0.0.0` و`process.env.PORT` فقط. لا تشغّل خادماً آخر للواجهة أو أمراً منفصلاً لمجلد server، ولا تثبت المنفذ على 3000 أو 8080. عدم وجود PORT أو كونه غير صالح يمنع الإقلاع بدلاً من تشغيل منفذ خاطئ. عند تعارض المنفذ يسجل التطبيق رمز الخطأ وينهي اتصاله بالقاعدة.

يمكن استخدام إعدادات البيئة في لوحة الاستضافة بدلاً من ملف `.env`، ولا تنشر ملف `.env` عبر الويب. لا تغير package.json إلى CommonJS؛ الحزمة تستعمل `"type": "module"`.

اضبط القيم الواردة في `.env.example`:
- `NODE_ENV=production`
- `PORT`: المنفذ الذي توفره خدمة Node.js.
- `MARIADB_DATABASE_URL`: عنوان القاعدة الجديدة بصيغة mysql:// مع ترميز الأحرف الخاصة في بيانات الدخول.
- احذف `DATABASE_URL` القديم وأي `MARIADB_TEST_SOCKET` أو `MARIADB_TEST_DATABASE`.
- `SESSION_SECRET`: قيمة عشوائية سرية لا تقل عن 32 حرفاً، واحفظها ثابتة بعد التشغيل.
- `DISABLE_STARTUP_SEEDING=true`
- `FRONTEND_DIST_DIR=./public`
- `APP_STORAGE_DIR`: المسار المطلق الحقيقي للمجلد الدائم الخاص. يمنع التطبيق المجلدات الرمزية والمسارات العامة.
- `PUBLIC_SITE_URL` و`PUBLIC_URL` و`PASSWORD_RESET_PUBLIC_URL`: ‏https://takyeh.sa
- `TZ=UTC`

تتضمن الاعتمادات ffmpeg-static لمعالجة الفيديو وsharp للصور؛ يجب السماح بتثبيتهما وتشغيلهما. عند استعمال pnpm يجب السماح بسكربت بناء ffmpeg-static. لا تنقل node_modules من Replit إلى الاستضافة؛ ثبتها على نظام الاستضافة نفسه.

أدخل مفاتيح مزود الدفع الحالي وإعدادات البريد بشكل آمن على الاستضافة عند الحاجة، دون تغيير التاجر. القيم السرية مستبعدة عمداً من التصدير. من دون إعداد المزود، لا يُعد إرسال البريد أو الدفع الحقيقي معتمداً. راجع إعدادات البريد الفعلية في التطبيق قبل إضافة متغيرات SMTP الاختيارية؛ تشغيل الصفحة وحده لا يثبت التسليم الخارجي.

## ٤. فحص الاستضافة والربط
ابدأ على رابط المعاينة الذي توفره الاستضافة قبل توجيه النطاق. تأكد من:
في هذه المرحلة اضبط `PUBLIC_SITE_URL` و`PUBLIC_URL` و`PASSWORD_RESET_PUBLIC_URL` على أصل رابط معاينة Hostinger نفسه بصيغة HTTPS، حتى تعود روابط الرفع والاستعادة إلى النسخة التي تختبرها. بعد تحويل النطاق غيّرها جميعاً إلى https://takyeh.sa وأعد تشغيل التطبيق.

1. `/api/healthz` يعيد `{"status":"ok"}`، والواجهة والهوية تظهر دون الرجوع إلى روابط تخزين Replit.
2. دخول حساب المدير الحالي وظهور الإعدادات، وعدم وجود بيانات ملاك أو حجوزات أو معاملات سابقة.
3. رفع صورة وإعادة فتحها بعد إعادة تشغيل التطبيق، واستمرار حجب الملفات الخاصة.
4. فحص الحجوزات والتقارير وموفر الدفع والبريد على الاستضافة ببيانات اختبار معزولة قبل اعتماد التشغيل.

بعد ذلك اربط takyeh.sa وفعّل HTTPS وفق إعدادات Hostinger. هذه الحزمة لا تغيّر DNS ولا تنشر نفسها.

## النسخ الاحتياطي والتحديث
انسخ قاعدة MariaDB والمجلد الدائم الخاص معاً وبشكل دوري إلى مكان منفصل، واختبر الاستعادة. عند إصدار تحديث انقل كود app فقط؛ لا تمسح القاعدة ولا المجلد الدائم، ولا تُعد تشغيل seed.sql.
