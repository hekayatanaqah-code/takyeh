---
name: Browser audit evidence
description: Reliable runtime DB evidence, real message text versus examples, and precise UI control scoping
---
Do not treat a tester's tool-backed SQL observation alone as proof that an API mutation failed to persist. Verify the same record through the application's actual database connection and capture the mutation response first.

**Why:** A photography approval test reported an approved UI badge but a pending tool-backed SQL result. A focused reproduction using the real API and direct application database reads consistently showed the approved state; the original mutation response had not been captured, so the earlier contradiction was not reliable evidence of a persistence bug.

**How to apply:** For a reported mismatch, collect the mutation URL and record ID, HTTP status/body, subsequent API read, and a direct read through the runtime database connection. Establish these facts before changing persistence logic or inferring that two tools share the same current state.

Development schema changes also need confirmation through the application's actual database connection. A successful tool-backed ALTER can affect a different database and leave runtime queries failing for missing columns.

**Why:** Adding photographer profile fields succeeded through the database tool, but the app's integration tests still reported missing columns and the application's own information-schema query returned none of the additions.

**How to apply:** Verify reviewed additive changes through the runtime connection before restarting or testing. If databases differ, apply only the scoped development DDL through the app connection; never infer that the tool's successful result changed runtime storage.

Template-editor examples are not evidence of the amounts in a real booking message. Distinguish illustrative preview data from the actual per-booking text generated by an action.

**Why:** A release audit mistook example refund and rental amounts in the editor for incorrect persisted booking calculations. The generated service cancellation text did expose a separate real omission, so treating all preview discrepancies as either real or harmless would both be wrong.

**How to apply:** Capture the actual booking-specific WhatsApp URL/text locally, compare it with the saved payment and refund state, and prevent external navigation. A generated prefill proves message formatting, not successful delivery. Also verify the precise filter region rather than inferring its layout from the unrelated owner account toolbar.

Matching aggregate totals does not prove that the intended lifecycle was tested. Confirm that a cancellation fixture is actually cancelled, rather than two active bookings coincidentally producing the expected sum.

**Why:** A financial retest displayed the expected property total using active bookings, leaving retained property-cancellation revenue unverified until an independent API check covered cancellations of future-year stays and partial refunds.

**How to apply:** Record lifecycle state and event dates alongside totals; use focused API checks for missing numerical cases instead of repeating a whole browser audit.

A browser download event alone is not proof of a valid PDF. Capture and inspect the actual bytes before cleaning the fixture or closing the browser context. Remote Playwright does not support Download.path(); use saveAs while the Download object is still available.

**Why:** A report export triggered a download, but its object was lost before retrieval, preventing honest certification of the PDF.

**How to apply:** Save the actual download immediately, inspect its content/pages, and mark PDF verification blocked if no file was obtained. Never substitute a separately rendered template as evidence of the app's real export.

Temporary PDF-verification tooling should not leave application deployment dependencies behind.

**Why:** Installing a renderer added native Nix dependencies and rewrote Python lock metadata; removing the Python package alone did not restore either.

**How to apply:** Compare the pre/post-install diffs and remove only audit-owned changes after verification. Use validated configuration replacement for `.replit`; do not reset whole files or overwrite concurrent work. Keep rendered evidence in the ignored generated-artifacts directory.
