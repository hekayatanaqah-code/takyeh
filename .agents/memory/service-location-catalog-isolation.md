---
name: Service location catalog isolation
description: Why service-provider locations must remain separate from property locations.
---

Service regions, cities, and districts must use an independent catalog and independent administration surface from chalet/property locations.

**Why:** The user explicitly requires service-provider coverage to be controlled separately so enabling or disabling a service location never changes the property submission options.

**How to apply:** Any service registration, coverage, location validation, or service-location administration must use the service catalog only. Do not reuse property location endpoints or tables.
