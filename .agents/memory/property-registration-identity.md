---
name: Property registration identity
description: Business meaning of duplicate property identity versus a similar name.
---

Treat a property name as a blocking duplicate only when its city and district also match; category is not part of that identity. The same name in the same city but a different district is allowed with a friendly advisory. A previously registered property WhatsApp number blocks registration, including equivalent local/international and Arabic-digit formats.

**Why:** The user explicitly requested these distinctions for the owner registration wizard. The previous name/city/category rule would wrongly reject properties in different districts.

**How to apply:** Keep early registration checks and final submission checks consistent. Do not later restore city-wide name uniqueness or make changing the property category a way around identity checks.

Property map links are not unique identities and must be shareable between registrations.

**Why:** The user explicitly allows common map pins for complexes and neighboring chalets.

**How to apply:** Do not use map-link equality as a registration or revision conflict, even when it matches an existing live listing.

Social account identity must survive equivalent URL/handle forms, letter case, and sharing parameters. An explicitly identified Instagram account and Snapchat account with the same username are distinct; a bare handle has no known platform and is conservatively checked against both.

**Why:** The user wants duplicate-account prevention for links as well as account identifiers. Raw URL comparison is bypassed by entering the same account as a handle; assuming a platform for an unqualified handle would miss duplicates.

**How to apply:** Use the same identity comparison for early checks and final writes. Exclude the current submission and its live mirror during edits.
